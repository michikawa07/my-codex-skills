# 主張の選択と決定

本文ページを作るとき，またはその主題を変えるときに使う．依頼で決まった目的・到達目標・必須条件を押さえ，複数の候補を挙げる．主題が指定済みなら，その範囲で事例，比べ方，説明順を変えて考える．各候補は「何を見せると，読み手は何を判断できるか」の組で記す．

## 説明を試し，候補を採点する

使う図・実物・データを先に確かめる．数値で示す差には，対象・条件・単位・比較基準が要る．図なら要点を略図に置き，文章なら具体例で説明してみる．例えば，測定波形から入れば，波形のどこを数値にしたかが分かる．集計図から入れば，条件間の差をすぐ比べられる．どちらがその場で必要な理解かで評価は変わる．[東京大学の発表資料の推敲例](https://www.ne.t.u-tokyo.ac.jp/makeslides/index.htm)

正確で，依頼の目的・必須条件に合う候補を，次の5観点それぞれで採点する．具体的な根拠がない場合は0点，一部を満たす場合は1点，求める理解・判断まで成立する根拠を示せれば2点とする．

| 観点 | 点数を付ける根拠 |
| --- | --- |
| 伝える目的への必要性 | 資料の目的に照らし，聞き手のどんな理解・判断・行動が変わるか． |
| 仕組みや関係を捉える重要性 | どの構造・依存関係・原因・結果が対象の理解を左右するか． |
| 読み手の理解を進める度合い | 聞き手が知っている経験や事実から，どんな新しい区別や説明にたどり着けるか． |
| この位置で扱う必然性 | 直前までに何を共有できていて，次の説明が何を必要とするか． |
| 具体的に説明できる見通し | 図・データ・実演のどこに着目すると，主張を確かめられるか．別の問いの答えになっていないか． |

合計点が最も高い候補を主張とする．残りは得点順に，主張の前提・理由・具体例・操作上の補足として必要かを検討する．主題候補としては点の低い前提でも，読者が問いを理解するのに必要なら先に共有する．候補・点数・根拠・採用案と前後のつながりをチャットで示してから，作図・レイアウトへ進む．

## 例に合わせて主張を狭めていないか

用いた例を別の例に替え，それでも残る主張を確かめる．仮に選んだ条件は，どの語が図のどこを指すか分かるように示す．その例を前のページの結びから続けて読み，どこまでが前提で，どこで初めて選択・結果の理由が分かるかを確かめる．[講義スライドの構成例](https://github.com/RinDig/lecture-deck-skill/blob/master/reference/storyboard-template.md)
