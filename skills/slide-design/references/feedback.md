# スライド制作で受けた指摘を次の判断に生かす

この作業を行うのは，依頼者と直接やり取りする制作・レビュー担当．構成や見せ方を決め始めるとき，またはスキルの見直しを依頼されたときに，前回以降の本人の発言を確認する．適用範囲に迷うものは，該当箇所，あり得る二つの扱い，推す案を添えて早めにまとめて相談する．設計中に迷いが生じたときは，その場で相談する．対象と仕上がりを指定された単発修正は編集と確認で完了し，次の制作時にその発言を読んでも担当が `[]` として扱う．独立校閲の担当には，確定した制作条件と教材を渡す．

## 前回以降の発言を読む

このスキルの `scripts/slide_feedback.py` を使う．資料フォルダーからは一番近い登録済みプロジェクトを使う．別のルートを指定するときはコマンドの前に `--project パス` を置く．プロジェクト内の記録は `.slide-feedback.sqlite3` 一つ．利用を始める案件では，本人とスライドを制作・レビューするスレッドを `watch スレッドID` で登録する．登録済みの案件で本人と新しい制作スレッドを開いたら，そのスレッドも登録する．委任した試行・サイドチャットは集めない．初回は履歴の先頭から，導入時点からの運用なら `--from-now`，特定の発言に続く期間なら `--after 発言ID` を選ぶ．発言IDは Codex のスレッド履歴にある userMessage の ID を使う．開始位置と確認済みの位置は区別して保存する．

`scan --output 一時ファイル.json` で，未解決の相談と，登録したスレッドの未処理発言が出る．出力先は一時フォルダーとする．発言には注釈元の選択文・本人のコメントや，質問と本人の回答が含まれる．履歴は当時の判断の根拠として読み，編集範囲は現在の依頼に従う．指摘が何を指すか分からなければ，そのスレッドの該当発言と当時の資料を開く．`more` が立っていれば処理後に続きを取る．履歴を開けないスレッドは `unavailable` に出て確認位置が保たれる．開けた分を先に進める．特定のスレッドだけを調べるときは `scan スレッドID`．

## 次にその選択をする場所に反映する

引用する言葉と，指摘を今回限りとするか今後どこまで適用するかを決めるときは，可能なら最新のClaude Opus（Claude Code CLIでは通常 `--model opus`）に相談する．本人の発言の全文に，対象が分かる前後のやり取りと，担当が考えた引用・適用範囲の案を添える．

発言を一つずつ読み，一つの発言にも資料固有の仕様と他に通じる判断があれば分ける．素材・研究内容の決定はその資料の制作情報，資料をまたぐ表現の判断は共通スキル，学習者への説明・実習・校閲に特有の判断は該当する講習スキルで扱う．まず採用済みの見本と既存の規則を引き，その規則を当時のページで使えばどう判断できたかを試す．既存の規則で防げたときは，制作・校閲でその規則を呼び出す箇所を調べる．一件の指摘から新しい共通基準を推定した場合は，作業用のコピーで試す．元の指摘を伏せた担当に，別の実例と今の表現を保つべき箇所を通常の入口から渡し，両方で意図した判断が出るかを確認してから共有する．図や編集設定の確認が必要なら，既存の実物点検を使う．転用の裏付けが取れた範囲までを制作に渡し，残りは元の版の事例として引けるようにする．現在の資料にだけ根拠がある条件は，その資料の範囲で扱う．

元の版で施した処置と，次の版でも満たすべき条件を切り分ける．処置を選んだ理由がある場合，後から原例を参照できるよう，その版の事例として保存できる．将来の制作に渡す文には，どんな場面で何が読み取れれば十分かを含める．別の表し方ですでにその条件を満たすページを一つ当ててみる．特定の配置・書式・文言まで継続仕様にする場合は，そこまで指定した本人の原文か，別の箇所でもその処置が必要になる実例を確かめる．

採用する判断を，次の担当が通常の制作で開く箇所に反映してから，一時ファイルの各発言の `decisions` を記入する．

- 単発の変更，質問，日程など，再利用する判断が残らない発言は `[]`．
- 当時の版に理由のある処置を施した実例は，`quote` に本人の原文，`place` にその版・箇所，`example` に何が読みづらく何を変えたかを書く．事例は由来を引くときだけ表示され，次の担当の制作指示には入らない．
- 反映済み・既存の判断は，`quote` に本人の原文の該当部分，`place` に根拠となる資料の版・箇所や対象，`file` と `rule` に実際の保存先とそこにある文の引用を書く．パスはプロジェクトルートから，スキルなら `skill:slide-design/SKILL.md` の形式．一つの発言から生じた複数の判断はこの配列に並べる．
- 範囲や意図が定まらないものは，`quote`・`place` と `question` を残す．その問いは次の `scan` の `open` に出る．本人の返答で採用先を決めたら，返答の発言で上記の保存先と `resolves: [相談番号]` を記入する．その一回だけと分かった場合は保存先の代わりに `local_only: true` を使う．

`apply 一時ファイル.json` は，本人の引用と保存先の文を実物に照らし，確認できたところまでを一度に記録する．未記入のままの発言や順番の飛びがあると，確認位置は進まない．続きの制作では通常の仕様・スキルを使う．あとで判断の由来を調べるときは `history --file AGENTS.md`，`history --id 番号` または `history --find 語句` で元の発言・資料との対応を引く．
