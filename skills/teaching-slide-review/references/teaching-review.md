# 講義設計と教材レビュー

概念の理解，判断や操作を学ぶスライドと配布物の設計・レビューに使う参照資料．学習者が既に分かることから，到達目標に必要な理解へ進める説明になっているかを判断する．

**到達目標と科目資料から整理した「身に付けるべき理解」と，教材を提示順に読んで得られる説明を照合する．** この二つを分けることで，下書きに書かれている内容だけに評価基準を合わせず，必要な意味・関係・判断が説明されているかを確かめる．

以下では，研究・授業設計資料の知見を引用し，それを教材へ適用する判断を示す．ここで組み立てたレビュー方法自体は，学習効果が実証された評価尺度ではない．教材から判断するのは説明の成立であり，学習者の実際の習得は回答や課題の結果で確かめる．

## 参照先の使い方

この資料を初めて使う際は，次の参照先の該当部分を読む．要約だけで判断がつかない場合も原資料へ戻る．科目の正確性を確かめる資料に加え，教える内容をどう分析するかについても，外部資料を判断に使う．

| 参照先と読む箇所 | レビューに使う内容 |
| --- | --- |
| Greg Wilson, [Teaching Tech Together](https://teachtogether.tech/en/)の「Mental Models and Formative Assessment」「Concept Maps」 | 初学者に必要な理解の枠組みと，概念・関係の整理．教える内容の構造と提示順を分けて考える [S13] |
| Merrill（2007），[A Task-Centered Instructional Strategy](https://files.eric.ed.gov/fulltext/EJ826059.pdf#page=7)のTable 1（PDFの7ページ） | 名称，部分，概念，手順，過程について，何を知ることと何ができることを区別するか [S14] |
| 既習内容の再掲を判断するとき：Merrill（2002），[First Principles of Instruction](https://mdavidmerrill.files.wordpress.com/2019/04/firstprinciplesbymerrill.pdf#page=4)のActivation（PDFの4〜5ページ） | 過去の経験を，新しい理解の土台として使うこと．単なる想起と，新しい内容を理解する枠組みの活性化の違い [S15] |

これらはレビュー者が判断の基準を作るための資料である．参照先の手法をすべて教材へ追加する指示ではない．

## 1. 何を理解させる教材かを定める

### 学習者の出発点と到達目標

既有知識は，新しい情報の解釈と学習に影響する．対象者について，経験した題材・操作と，説明・判断できる概念を分けて把握する．操作できたことだけから，仕組みまで理解しているとは判断できない．前の教材や課題の回答を確認できる場合は，何が説明され，どこまで確かめられたかを参照する．不明な理解を，既知として扱わない．[S1]，[S2]

到達目標は，「条件の違いによる結果を説明できる」「目的に合う方法を理由とともに選べる」のように，学習者が示す説明・判断・行動として定める．必要に応じ，使用できる資料や道具，到達と認める条件・基準も明らかにする．「何を教えるか」という項目名だけでは，学習の成立を判断できない．[S3]，[S4]

教材に示す目標でも，学ぶ概念・仕組み・技能が伝わるかを確かめる．道具，実習の題材，作る成果物は，その目標との関係を示す．タイトルと本文から，何を学ぶ回・単元なのかを読み取れるようにする．〔[S3]を目標の提示へ適用した判断〕

### 到達目標に必要な理解を，科目資料から整理する

まず，依頼で示された学習対象と目標を，信頼できる科目の基礎教材・仕様・実例で確認する．重要概念の意味，概念同士の関係，使う理由を短く説明できるようにする．この基準は，初学者が目標へ到達するために必要な範囲へ絞る．専門資料にある全機能や例外を，入門教材の必須事項にしない．〔[S1]，[S3]，[S6]をレビューへ適用した判断〕

知識の組織化の仕方は学習と適用に影響する．Wilsonは，初学者が事実を結び付ける理解の枠組みを作ることと，概念の関係を整理してから説明順を考えることを論じている．レビューでも，下書きの見出し順や記載事項をそのまま基準にせず，学習対象の構造を先に整理する．概念図はそのための一つの手段であり，図の作成自体を必須にはしない．[S1]，[S13]

整理する際は，何を学ぶのかに応じて，説明の成立条件を変える．MerrillのTable 1は，記述を覚えることと，具体的な対象に適用できることを次のように区別している．[S14]

| 学ぶ内容 | 説明を覚えること | 具体的な対象に適用すること |
| --- | --- | --- |
| 対象についての情報 | 名前・記述を知る | 記述に当たる実際の対象を特定する |
| 部分と全体 | 部分の名前・記述を知る | 全体の中で，その部分を位置付ける |
| 概念・種類 | 定義となる性質を知る | どの具体例がその概念に当たるかを見分ける |
| 手順 | 手順の順番を知る | その順番で実行する |
| 過程・仕組み | 条件と結果の記述を知る | 条件から結果を予測し，結果から必要な条件を考える |

例えば，部分の位置や包含関係が説明されていても，その全体や部分が何を指すかまで説明されたとは限らない．概念を教える説明なら，**何をその概念と呼び，具体例のどのまとまり・性質がそれに当たるのか**を読み取れる必要がある．「単位」「機能」「仕組み」などの一般語へ置き換えただけで，対象を特定できる説明になったと判断しない．これは上表を概念説明のレビューへ適用する判断であり，すべての概念に分類問題や非該当例を追加する要求ではない．

重要概念では，どんな課題・要求に応え，どの性質によって何が可能・容易になるかも整理する．「便利」「再利用できる」という利点の名称だけでは，選ぶ理由や使う条件の説明にならない．仕組みから推論した利点，説明用に設定した課題，実際の成立経緯・設計意図は区別し，後者は出典で確認する．〔[S1]，[S6]を適用した判断〕

ここまでで，目標に必要な理解を確かめる問いと，基準となる答えを少数作る．概念なら「具体例のどの対象を，なぜそう呼ぶか」，仕組みなら「条件を変えると何が起こり，なぜか」などである．この問いはレビュー者が説明の充足を判定するために使い，そのままスライドや実習へ追加する項目とはしない．

学ぶ価値と達成できる見通しは，動機づけにも関わる．具体的な使い道，取り組める課題，進歩を確かめる機会を，学習目標に結び付ける．学習への到達，必要な時間・資源，学ぶ意欲はそれぞれ評価し，面白い題材や好評だったことだけを学習成立の証拠にしない．[S1]，[S4]

## 2. 必要な理解と，提示順に読み取れる説明を照合する

科目資料から作った基準の問いを持って，最初のページから読む．学習者の既有知識と，そこまでに説明された内容を使い，問いの答えを本文・図からどこまで組み立てられるかを確認する．外部資料はレビューの基準を作るために使い，学習者が読んだ資料として不足を補うことはしない．

主題，前提，用語・図の意味，提示順，強調と読みやすさは共通して確かめる．以下の講義用・作業用の観点は，ページの活動と到達目標に合わせて使い，説明と課題を併用する場合は組み合わせる．第1節の学ぶ内容の分類とは別に，教材の使い方に応じて確認するための観点である．

### タイトルと本文が，何を学ぶ説明を示すか

本文と図を読み，ページが何を理解させるかを特定する．その内容を，第1節で整理した学習対象と照合する．下書きが実際に扱う項目と，その段階で理解させる必要がある概念・関係が食い違う場合は，その差を指摘する．実際に描かれた関係が正しくても，必要な概念そのものの説明を代替するとは限らない．

目標のページでは，学習対象，使用する道具・方法，題材・成果物を区別する．見出しが何を目標として強調し，本文が何の理解・技能を目標としているかをそれぞれ読む．本文に学習項目があることだけで，見出しも同じ主題を伝えているとは判断しない．〔[S3]を目標の提示へ適用した判断〕

個々のページでも，定義，関係，作成方法など，タイトルが予告する説明と内容を照合する．役割が違えば，何を学ぶページかに関わる問題として扱う．主張と視覚的な説明を組み合わせる設計には研究があるが，すべてのタイトルを結論文にするという形式上の規則にはしない．[S12]

### 講義用：本文と図で，基準の問いに答えられるか

**基準となる理解と，教材から得られる説明を別々に記述し，差を確かめる．** 「用語がある」「図に関係がある」という確認で止めず，学習者が答えを組み立てるために，どの記述・図・既有知識を使えるかを対応付ける．問いに必要な対象や関係が欠ける場合，別の関係の説明が成立していることをもって合格としない．

概念の説明では，定義のどの性質が具体例のどの部分に当たるかを読み取れるかを見る．抽象的な表現と具体例の対応を明示することは，研究に基づく実践指針でも推奨されている．[S7]（勧告4）

図では，対象，線や矢印，配置，注釈が，何の関係・変化を表すかを確かめる．本文と図中の対象を対応付けられ，重要な関係へ注意を向けられる必要がある．無関係な情報の削減，構造を示す手掛かり，対応する語句と図の近接は，マルチメディア学習の研究で検討されている．[S11]

コードやデータ構造は，科目で実際に使う記法と照合する．図解や簡略化を使う場合も，実物のどの要素・関係を示すかを追える必要がある．

判断は，「部品の包含関係は分かるが，その部品が何を指すかを特定できない」「名前を合わせる条件は分かるが，その仕組みを選ぶ理由は説明されていない」のように，成立と不足を分けて示す．科目資料や専門知識でレビュー者が補った意味・因果を，教材から読み取れた説明に含めない．

### その説明を，その位置に置く寄与を判断する

読む順序は，ページ間とページ内の両方で追う．予告や問いで示した用語は，意味の説明が済んだ用語と区別する．先のページに説明があっても，そこへ至る途中で理解に必要なら，その段階の前提不足として扱う．

既習内容の再掲では，その経験を基に，何の概念・関係を理解し直すかを確認する．Merrillは，過去の経験を新しい知識の土台へ結び付けることを論じ，単純な想起だけで十分とはしていない．[S15] この観点から，再掲で注目させる事実と，続く説明でその事実をどう使うかを照合する．「復習になる」という役割名で，寄与の説明を済ませない．

そのページを省略した構成と，次の概念説明へ統合した構成も考える．どの理解の手掛かりが失われ，何が保たれるかを，比較して残し方を判断する．独立させる必要性の根拠がない場合は，その点を示す．再掲の価値を，単に新しい情報があるかどうかで決めない．

具体例は，その時点の学習者が理解できるものを選ぶ．既に扱った題材でも，経験のどの部分を概念へ結び付けるかを示す．未知の題材なら，その題材を理解するための前提も必要になる．後で行う実習を，経験済みの例として扱わない．〔[S1]，[S2]，[S7]を例の選択へ適用した判断〕

不足を見つけたら，内容の誤り，説明の欠落，順序，題材の選択のどこに原因があるかを考える．既存の説明の修正・移動・統合・削除を含め，理解を成立させる変更を選ぶ．遠いページや実習との対応は，その時点で必要な意味と説明の接続を確認したうえで評価する．

### 作業用：課題に必要な情報から，活動と判断を進められるか

課題で与える前提・指示・材料と，学習者が考える範囲を，到達目標と既有知識から区別する．必要な支援と，目標となる判断を学習者に委ねる範囲は，第3節と照合する．

操作を教える場合は，受講者の環境と開始状態から手順を追う．操作対象・場所，行う動作や必要な入力，操作後に確認する状態を教材から判断できるかを見る．新しく教える操作に必要な情報は，その作業ページに示されていることを確かめる．既習の操作を参照するときも，参照先と何をどこで使うかを特定できる必要がある．

操作手段に応じて，端末のコマンド・対話入力・キー操作，GUIの画面・項目，実機の接続先・操作部・設定値などを確かめる．課題の方法・手順自体が成立することと，学習者が教材から必要な判断・行動を行えることを分けて評価する．コードを実行する課題では，コードの動作確認も行う．

順に行う操作と，条件や目的に応じて選ぶ方法が，提示から区別できるかを見る．主手順と補足，条件分岐，選択肢と判断基準の並列提示などが，学習目標と習熟に合っているかを確かめる．複数の画面・端末を使う場合は，操作先と継続中の処理や状態も追う．

## 3. 説明・課題・理解の確認を対応させる

学習目標，学習活動，到達を確かめる課題は対応させる．方法を選ぶことが目標なら，名称を答えるだけの課題では，選択の判断を確かめられない．選ぶための基準を説明し，判断を練習でき，回答からその理由を確認できる必要がある．[S5]

課題では，与えられた情報や活動の結果から，何を予測・比較・説明・判断するかを見る．教材を操作すること，提示された情報を受け取ること，情報を基に自分の説明を生成することなどは，学習への関与として区別される．実行や参加の外形だけから，どんな理解が成立するかを決めない．[S9]

説明と自力で考える範囲は，到達目標と習熟に応じて決める．解答過程を示す例と自分で解く問題を組み合わせることには研究上の支持がある．支援は課題を進める助けになる一方，自分で判断する機会を減らす場合もある．教材には，学ぶべき判断まで代行していないか，考えるために必要な前提を省いていないかを見る．[S7]（勧告2），[S8]

理解の確認には，理由や仕組みの説明，学んだ内容を思い出す問い，間隔を置いた再学習などが使える．問いには，何を理解した回答かを判別する基準と，必要に応じて解説やヒントを用意する．確認結果を学習の支援へ返すことが重要であり，問いや記録の数を増やすこと自体を目的にしない．[S1]，[S7]（勧告1，5b，7），[S10]

スライドと配布物では，読む条件と用途に合わせて情報を配置する．受講後に参照する説明や，コピーして使うコマンドも，その用途に必要な内容として評価する．音声と画面文章の重複に関する研究結果を，配布物の説明を削る根拠へ機械的に転用しない．〔[S11]からの適用上の判断〕

## 4. 判断の根拠と，優先する修正を伝える

レビューでは，対象の版・範囲と，前提にした学習者の知識を明らかにする．提示順に読んで，最初に理解が途切れる箇所と，そこから影響を受ける説明を特定する．そのうえで，教材全体の内容・課題・到達目標の対応を判断する．

指摘には，**目標に必要な理解，該当する記述・図から読み取れる説明との差，学習への影響，修正後に成立させたい理解**を示す．良いと判断する場合も，どの記述が何の理解を支えるかを根拠にする．

修正の優先順位は，到達目標に必要な理解をどれだけ妨げるか，後の説明へどれだけ影響するかで決める．技術的誤り，意味の不明な定義，学習対象の不明確さ，必要な前提・関係の欠落を，説明の成立に関わる問題として扱う．同じ原因の問題はまとめ，制作側が判断すべき表現・配置まで細かく指定しない．

説明が成立する範囲での改善提案には，期待する効果と変更の負担を示す．既有知識や利用条件によって結論が変わる場合は，判断に必要な情報とその影響を示す．修正後は，求めた理解を実際の本文・図から得られるかと，前後の説明への影響を確認する．

構成案は，記載された説明内容と接続の範囲で判断する．視認性の判断には実際のスライドを，手順や配布コードの動作確認には実行環境・条件と結果を使う．確認した範囲に応じて結果を伝える．

図・表の読み方，ページ内の依存関係，書式・スタイルと表示の確認は，[slide-design](../../slide-design/SKILL.md)と対象プロジェクトの指定に従う．この資料では，それらが学習対象と説明の意味・順序を伝える働きを評価する．
